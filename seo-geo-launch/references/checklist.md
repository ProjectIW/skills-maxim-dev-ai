# Чек-лист SEO и GEO с командами

`D=https://[ДОМЕН]`. Все проверки только читают.

## 0. Исходная точка

```bash
# роботы в журнале прокси (пример для JSON-журнала Caddy) за всё время журнала
zcat -f [ЖУРНАЛ]* | jq -r '.request.headers["User-Agent"][0] // "-"' \
  | grep -oiE "YandexBot|YandexAdditional|Googlebot|GoogleOther|bingbot|GPTBot|OAI-SearchBot|ChatGPT-User|ClaudeBot|Claude-SearchBot|PerplexityBot|Applebot" \
  | sort | uniq -c | sort -rn

# каждая открытая страница: код, canonical, title, description, og
for p in / /[СТРАНИЦА1] /[СТРАНИЦА2]; do
  h=$(curl -s "$D$p")
  echo "$p $(curl -s -o /dev/null -w '%{http_code}' "$D$p")"
  echo "$h" | grep -oE '<link rel="canonical"[^>]*>|<title>[^<]*</title>|<meta (name|property)="(description|og:[a-z:]+)"[^>]*>' | head -10
done

curl -s -o /dev/null -w '%{http_code}\n' $D/favicon.ico
curl -s $D/robots.txt; curl -s $D/sitemap.xml | head -30
```

Признаки беды: canonical у всех страниц один и тот же; `noindex` на открытых страницах; sitemap с одной датой у всех; 404 на `/favicon.ico`; ни одного поискового робота за сутки.

## 1. Техника

- [ ] Один список открытых страниц, из него sitemap, llms.txt, IndexNow.
- [ ] Свой canonical и og:url у каждой страницы; в корневом макете canonical нет.
- [ ] robots.txt обработчиком: Clean-param, группы роботов, закрытое повторено в каждой группе, `Sitemap:` полным адресом.
- [ ] sitemap: `lastmod` – дата изменения страницы.
- [ ] schema.org: один граф, цены из источника тарифов, без несуществующих отзывов и оценок; `dateModified`.
- [ ] llms.txt и llms-full.txt: дата «Обновлено», только проверенные факты, без контактов и поставщиков по умолчанию, текст согласован.
- [ ] RSS новостей.
- [ ] IndexNow: ключ в файле `/[КЛЮЧ].txt` и в коде (менять вместе), отправка только изменённых, журнал отправленного.
- [ ] Служебные страницы: `noindex` и заголовок `X-Robots-Tag`.
- [ ] Публичные страницы не отдаются с `Cache-Control: no-store` без необходимости: рендер на каждый запрос заметно увеличивает TTFB, а скорость ответа учитывают и поисковики, и люди.

Проверка IndexNow вручную:

```bash
curl -s -o /dev/null -w '%{http_code}\n' -X POST https://api.indexnow.org/indexnow \
  -H 'Content-Type: application/json; charset=utf-8' \
  -d '{"host":"[ДОМЕН]","key":"[КЛЮЧ]","keyLocation":"https://[ДОМЕН]/[КЛЮЧ].txt","urlList":["https://[ДОМЕН]/"]}'
# 200 или 202 – принято
```

Bing может проверять пример ключа из своей документации (`0123…cdef.txt`) – 404 на него не ошибка.

## 2. Кабинеты

| Кабинет | Подтверждение | После подтверждения |
|---|---|---|
| Google Search Console | HTML-файл `google[хеш].html` в корне | sitemap, проверка URL главной |
| Bing Webmaster | импорт из Search Console | sitemap, IndexNow уже работает |
| Яндекс Вебмастер | HTML-файл `yandex_[хеш].html` | sitemap (если раздел работает), переобход главной и новостей, регион, главное зеркало, диагностика |

Файл подтверждения кладётся в папку статики и выкладывается версией. Проверь, что он отдаётся роботу: `curl -A "Mozilla/5.0 (compatible; YandexBot/3.0)" $D/yandex_[хеш].html`.

## 3. Превью

```bash
curl -s $D | grep -oE '<meta property="og:(image|video|title|description|url)[^"]*" content="[^"]*"'
# адреса og:image и og:video должны начинаться с https://
```

- [ ] og:image 1200×630, PNG или JPG, полный адрес.
- [ ] og:video (mp4) полным адресом, если нужна анимация в Telegram и Discord.
- [ ] Заголовок превью без повтора бренда, если бренд уже в og:site_name.
- [ ] В картинках превью нет реальных имён людей.
- [ ] Новая картинка – новое имя файла.

## 4. Метки

- [ ] Список меток в коде (метка → канал → подпись в отчёте).
- [ ] Метки попадают в аналитику визита и в «первый канал» посетителя.
- [ ] Для каждой метки, которую будут постить в Telegram, прогрето превью.

## 5. Таблица запросов для посадочных

Столбцы: запрос; точная частота (Wordstat с «!»); цена клика из прогноза Директа; число слов; геозависимость; намерение (коммерческое или информационное); уровень агрегирования первой десятки (доля подборок, агрегаторов, маркетплейсов); есть ли у нас ответ. Брать длинные, геонезависимые, с коммерческим намерением и низкой агрегацией.

## Реклама: что важно знать для России

Положение меняется – перед решением проверь актуальность каждого пункта.

- **Google Ads:** показ рекламы в России приостановлен с 2022 года, российские карты не принимаются, маркировку через ОРД не сделать. Имеет смысл только для других стран, но оплата тарифа иностранной картой через российского эквайера обычно невозможна. Проверка: в мастере кампании на шаге выбора мест Россия недоступна.
- **Microsoft Advertising и рекламные кабинеты зарубежных ИИ-ассистентов:** для российских рекламодателей и аудитории, как правило, недоступны – проверь на момент запуска.
- **Яндекс Директ** – основной рабочий канал. Брендовая кампания после индексации; кампании на те же длинные запросы, что и посадочные. Стратегии «за конверсии» требуют Метрики; если в продукте своя аналитика без сторонних счётчиков, подключать ли Метрику – вопрос к владельцу продукта. Брендовую кампанию не выключать вслепую: проверить чередованием 2 недели вкл/выкл. Решения о бюджете не принимать по первой неделе.
- **Маркировка:** реклама в интернете для россиян маркируется (erid) и передаётся в ОРД (38-ФЗ, ст. 18.1). Посевы в каналах и статьи на заказ – тоже.
- **Замены Директу:** VK Реклама по ключевым фразам, Telegram Ads и посевы, Авито, подборки и статьи (vc.ru, Хабр).
- **Проверка рекламного кабинета Google** создаёт пачку визитов из дата-центров Google (Маунтин-Вью, Лондон) – в аналитике это не люди.
