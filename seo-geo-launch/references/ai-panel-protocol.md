# Панель ИИ-ответов: протокол

Цель – раз в 2 недели честно измерить, называют ли ассистенты продукт, и не обманываться единичными ответами. Ответы ассистентов нестабильны: один и тот же запрос в разных прогонах даёт разные источники, а часть прогонов поиск вообще не включает.

## Запросы (20–30)

Три группы, примерно поровну. В примерах ниже – условный продукт из категории «учёт заявок для небольшого бизнеса»; подставь свою категорию.

1. **Узнавание по имени:** «Что такое [ПРОДУКТ]?», «[ПРОДУКТ] [категория] отзывы», «Сколько стоит [ПРОДУКТ]?». Новые продукты узнаются по имени почти всегда, если страница в индексе.
2. **Категория:** «сервис учёта заявок для малого бизнеса», «как автоматически распределять заявки между менеджерами», «простая CRM на русском». Здесь видимость нового продукта обычно единицы процентов.
3. **Задача с ограничениями:** «учёт заявок с хранением данных в России», «CRM с интеграцией с 1С для небольшой компании», «[категория] для салона / для автосервиса». Отличия продукта работают именно здесь.

Для каждого запроса – 1–2 перефраза: перефраз меняет результат.

## Ассистенты

Алиса или Нейро (индекс Яндекса), GigaChat, ChatGPT с поиском, Perplexity, Copilot. Для каждого запроса – 2 прогона в новом чате, без входа или с чистой историей.

## Что записывать (таблица)

| Поле | Значение |
|---|---|
| дата, ассистент, запрос, № прогона | |
| поиск включился | да / нет / не видно |
| продукт назван | да / нет |
| место в списке | 1, 2, 3… или – |
| ссылка на наш сайт | да / нет, какая страница |
| факты о продукте верны | да / ошибки: какие |
| конкуренты в ответе | список |

Пустой ответ и «не нашёл» – тоже данные, их записывай.

## Итог

- Доля прогонов с названием продукта по каждой группе отдельно.
- Ошибки в фактах – что поправить на сайте и в llms.txt (цены, даты, где обработка).
- Сравнение с прошлой панелью. Изменение на 1–2 прогона из 30 – шум.

Не покупай «GEO-пакеты» и не обещай рост «на 40 %»: в обзорах исследований такие числа не подтверждаются как общий результат.
