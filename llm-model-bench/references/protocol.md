# Протокол стенда моделей

## 1. Эталоны

**Свои записи.** Только внутренние, с согласия участников. Для каждой – истина, проверенная по самой записи: длительность, число людей, кто где говорит (хотя бы по фрагментам), домен. Пример набора: созвон двоих (10–20 мин), совещание 4–6 человек (30–60 мин), выступление с вопросами из зала (около часа), разговор в шумном помещении.

**Озвученные сценарии.** Пиши текст встречи с репликами по ролям (продажи, подрядчик, педсовет, совет директоров, ИТ-команда с английскими терминами, диалог с паузами), озвучь разными голосами, сохрани TSV истины:

```
start_sec	end_sec	speaker	text
0.00	4.20	S1	Добрый день, коллеги, начнём с бюджета на третий квартал.
4.45	9.10	S2	Сумма – два миллиона четыреста тысяч, срок до конца месяца.
```

Голоса синтеза бывают похожи между собой: если модель сливает двух «людей» только на озвучках, а на настоящих записях различает, это ограничение эталона, а не модели. Для 3–4 говорящих нужны и настоящие записи.

**Шум.** Добавь розовый шум −50 дБ ко всем озвучкам (`scripts/add-noise.sh`, фиксированный seed), сухие храни как `<имя>-dry.wav`. Каноническим эталоном считай шумный.

**Граничные длины** склей из озвучек под свою нарезку: [длина куска + несколько секунд], [кратно куску + хвост короче нахлёста], чуть больше часа, 3+ часа, 3 с тишины (должна уйти в понятную ошибку, а не в пустой результат).

## 2. Бюджет

```
Кандидатов: [N] (включая текущую модель)
Эталонов: [M], общая длительность [T] ч
Прогонов: 2
Оценка: N × T × 2 × [цена за час] + вызовы LLM [K] × [цена] ≈ [сумма]
```

Согласуй с владельцем продукта до запуска. Превышение больше чем на 30 % – остановка и вопрос.

## 3. Запуск

- Стенд использует боевой конвейер: тот же образ или дерево той же ревизии. Если для опыта нужна правка, она идёт коммитом, а не ручной правкой файлов стенда.
- Окружение: ключи только моделей, без почты, платёжки, ботов, телеметрии. Ключи передавай трубой в `--env-file /dev/stdin`, не сохраняй в файлы стенда.
- Выходы складывай в `out/<метка>/<эталон>.json` с меткой модели, версии и даты.
- Стенды на видеокарте не поднимай рядом с боевыми сервисами: памяти не хватит обоим. Опыты – через боевые сервисы в тихое время или на отдельной карте.
- Фоновые циклы замера (`while true; nvidia-smi`) гаси сразу после замера.
- `pkill -f <шаблон>` в ssh-команде убивает и саму сессию, если шаблон есть в её строке: пиши `pkill -f "[н]азвание"`.

## 4. Замер скорости и памяти

```bash
# время на час записи: (секунды обработки / длительность в секундах) × 60
# память видеокарты во время прогона
nvidia-smi --query-compute-apps=pid,process_name,used_memory --format=csv -l 1 > gpu.csv &
# память и CPU контейнера
docker stats --no-stream --format "{{.Name}} {{.CPUPerc}} {{.MemUsage}}" [КОНТЕЙНЕР]
```

Одновременность: 1, 3, 6 записей разом; записывай время каждой, ошибки, пик памяти. Пересчитывай в «часов записи в час».

## 5. Отчёт

HTML: таблица метрик, слепая оценка, скорость и память, цена, рекомендация, что не проверено, где лежат эталоны и выходы. Копии реальных записей на стенде удали после оценки, эталоны (озвучки и истину) оставь для следующих сравнений.
