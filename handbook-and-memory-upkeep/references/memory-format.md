# Формат заметки памяти

## Файл

Имя – латиницей через дефис, с проектом и темой, при необходимости с версией или датой: `[проект]-[тема]-[версия|дата].md`, например `shop-catalog-cache-2-3-1.md`, `shop-audit-[ГГГГ-ММ-ДД].md`.

```markdown
---
name: [имя файла без .md]
description: "[Одна фраза: что за факт и главное число или решение. По ней заметку находят.]"
metadata:
  type: [project | feedback | reference | user]
---

[Факт: что произошло или что решено, с датой, версией, коммитом. Конкретно: числа, пути, имена файлов кода.]

**Why:** [почему это важно; кто решил и когда; формулировка правила, если оно задано.]
**How to apply:** [что делать в следующий раз: команда, проверка, запрет.] Связано: [[другая-заметка]].
```

## Типы

| Тип | Что | Пример |
|---|---|---|
| feedback | правило или предпочтение, принятое в проекте | «Видимые правки главной – только после отдельного согласования»; «в интерфейсе без средних точек» |
| project | состояние и решения по проекту | «Аудит [дата]: [N]/100, P0 …»; «на сервере очередей не включать автообновление ядра» |
| reference | как сделать | «Стенд проверки в браузере: как поднять, ловушки» |
| user | о человеке, с которым работаешь | роль, зона ответственности, как удобнее получать отчёты |

## Хорошая и плохая заметка

Плохо (лог, а не знание):

> Вчера сделал много всего: 2.3.0–2.3.4, кеш, письма, тарифы, скорость.

Хорошо (один факт, причина, применение; пример выдуманный):

> [ДД.ММ.ГГГГ], v2.3.1: кеш ответов каталога включён без сброса при изменении цены – покупатели около часа видели старые цены.
> **Why:** проверяли только скорость ответа, не свежесть данных.
> **How to apply:** при добавлении любого кеша – сразу сценарий сброса и тест «изменил данные – увидел новое».

## Индекс `MEMORY.md`

```markdown
- [Проект: тема](файл.md) – главное в одной строке (число, решение, дата)
- [Проект: аудит [дата]](shop-audit-[дата].md) – (устарел, см. [новая]) [N]/100 на [версия]
```

Правила индекса: одна строка на заметку; до ~150 знаков; без списков версий; устаревшие в конце раздела или с пометкой. Если индекс длиннее ~60 строк – сведение.

## Чек сведения памяти

1. Найди заметки по одной теме (аудиты, выкладки, одна подсистема).
2. Слей в одну актуальную, старые пометь «устарел, см. …» или удали, если в них нет уникальных уроков.
3. Проверь факты против кода и сервера: версии, пути, решения.
4. Из индекса убери подробности, оставь указатель.
5. Убедись, что правила (feedback) не потерялись при слиянии.
